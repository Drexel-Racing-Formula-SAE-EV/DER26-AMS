# r10: explicit C-path acquisition and common ADC trigger

Base: r9; revision TIMING9-CPATH. “One working channel” is interpreted as C-ADC operational and S-ADC redundancy unavailable, not one physical cell voltage being available.

C_ONLY_MVP previously selected C measurement authority but still commanded RD_ON redundant C/S conversion and waited 17 ms. It now explicitly commands RD_OFF, continuous C, and waits 9 ms after each restart (one full 8 ms AVG8 window plus margin). This saves 8 ms of scheduled wait per normal acquisition. It deliberately retains restarting each scan rather than introducing an unqualified persistent-continuous state. Raw C, coherent SNAP, CCTS freshness, PEC, command counters, reference readiness, OV/UV and all required cell masks remain enforced. No missing cell is newly excluded. Redundant mode and its wait are retained for future qualified hardware. Periodic S diagnostics remain disabled by default. Status flag observations remain available but do not turn C-only measurements into redundancy-qualified data. Profile-3 release evidence gates remain.

An optional `AMS_CURRENT_TIMER_TRIGGER=1` is added only to the existing inhibited ALLIO preset. It requires paired-start mode and profile 4. Both current ADCs are armed for the same TIM8 TRGO update event, then a single UG event triggers both. TIM8 remains stopped: there is no extra timer ISR or autonomous sampling schedule; the current task retains its 50 Hz cadence and mutex. The timer is refused if configured by another subsystem; enabled ADCs are refused before trigger configuration. Original ADC trigger settings are restored after both stop attempts on success or failure. Existing shared polling timeout, pair validity, calibration and range/fault policy remain. This is a hardware common-trigger candidate, not ADC DMA or hardware qualification. The ADCPAIR isolated preset still uses software paired starts.

Tests: actual-source ADC tests cover both arms before polling, common trigger routing, ownership refusal, trigger restoration, partial failures and timeout/tick wrap. Actual-source ADBMS tests explicitly assert the C-only ADCV command has RD_OFF. Full vehicle CI, combined target-branch native syntax and Stage 4/5 ASan/UBSan results are in validation/STAGE5_CI.txt and STAGE5_SANITIZERS.txt. Synthetic HAL/MMIO tests do not measure physical trigger skew, ADC conversion completion or isoSPI behavior. No ARM target build/link or hardware test was performed.

Still outstanding: splitting the mandatory C open-wire routine. It remains synchronous and always restores a checked normal C image. This update does not claim that routine has been decomposed or that the whole system has a guaranteed 100 ms WCET. The prior r9 review describes UART DMA/AUX polling and earlier changes; its timer-trigger limitation is superseded only by this optional common-trigger candidate.

Hardware acceptance: compare standard C-only timing and SPI/CCTS/PEC counters with r9; verify all 75 required cell readings and normal C restoration after diagnostics. Compare ADCPAIR with ALLIO while checking current validity and task gaps; scope both ADC timing before enabling outside bench. In ALLIO, UART DMA and AUX polling are also selected, so use manual isolated timer flag or account for these differences when attributing performance.

Primary reference: ST RM0410 ADC external-trigger mapping and TIM8 master-mode update event. The included ST HAL defines ADC_EXTERNALTRIGCONV_T8_TRGO and ADC_EXTERNALTRIGCONVEDGE_RISING; HAL_ADC_Start checks hardware EXTEN before issuing software start. ADBMS6830B conversion commands and C update rates are documented in the supplied Analog Devices datasheet.
